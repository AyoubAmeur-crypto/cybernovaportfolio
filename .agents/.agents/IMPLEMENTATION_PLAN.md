# Implementation Plan

## 12. Implementation workflow
Phase 1 — Repository and design analysis.

- Inspect the current implementation.
- Read the `.agents` instructions.
- Retrieve the Figma design context and screenshots.
- Identify section patterns and design tokens.
- Map Figma sections to cybersecurity content.
- Identify missing professional information.
- Produce an implementation plan.

Do not edit the existing implementation during Phase 1.

Present the analysis and plan for approval before implementation.

Phase 2 — Foundation.

- Establish design tokens.
- Prepare reusable components.
- Implement the glass navbar.
- Configure Lenis and GSAP integration.
- Implement the hero-to-content transition.

Phase 3 — Content sections.

- Implement the remaining sections based on Figma.
- Integrate verified professional content.
- Prepare data-driven projects, collaborators and testimonials.

Phase 4 — Refinement.

- Refine spacing, typography and visual hierarchy.
- Validate the Figma fidelity.
- Optimize animations.
- Test responsiveness.

Phase 5 — Validation.

- Run linting.
- Run type checking.
- Run existing tests.
- Run the production build.
- Validate desktop and mobile layouts with browser screenshots.
- Check the browser console.
- Check accessibility and performance.
- Confirm that the existing hero has not been broken.
